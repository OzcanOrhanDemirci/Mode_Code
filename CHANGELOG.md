# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- A reset at a task boundary could go on without its `/clear`: it ran the command a moment after refusing the call, and Claude Code refuses a command while that call's hook still holds the turn. The conversation went on with "the reset did not go through" and the refused call had to run again (three times in one evening). The `/clear` now runs once the turn it ended is over.
- In a repository that takes changes only through pull requests, pushing a branch such as `release/1.2.1` was stopped as a push past them: the belt counted every protected branch, the default `release/*` pattern too, where pull requests merge only into the branches named whole (`main`, `master`). A force-push to `release/*` is still blocked.
- A script handed to an interpreter that only mentioned a delete in a string, such as one editing another script's `rmSync(dir, { recursive: true })` line, made every path it named count as deleted, and its own output file read as a recursive delete outside the project. A delete in a string or a comment is no call of the code's own now: what it is given still counts, a name it leaves unknown only that string's own paths.

## [1.2.0] - 2026-10-27

One protection, three ways of working: the safety belt decides by how you chose to work, keeps what a risky step takes away before it runs, and weighs a step's target by where it came from. Full autonomy becomes an ordinary way of working in place of 1.1's runs and bypass, a cockpit beside the conversation says what Claude may do right now, and the control center is arranged by what you come for, every setting saying what it does where it stands.

### Highlights

- **The way of working decides how much is asked** ([docs/safety-belt.md](docs/safety-belt.md#ways-of-working)). The rules are the same in Manual, Autonomous and full autonomy; each says what it does in each. Manual asks; Autonomous asks where it matters; full autonomy asks nobody and leaves a step only you may take to you, with its exact command, while the rest of the work goes on. 54 rules in fourteen groups.
- **A safety net** ([docs/safety-belt.md](docs/safety-belt.md#safety-net)). In Autonomous and full autonomy a hard reset, `git clean`, a force-push or a delete outside the project runs once what it takes away is kept, instead of being asked. `mode-code net` lists what was kept and puts it back.
- **Evidence** ([docs/safety-belt.md](docs/safety-belt.md#evidence)). A target you named in the session counts as your word; a host, a path or a command found only in what the session read from outside is refused in every way of working.
- **Three more families in the belt**: data sent off the computer (`outbound.network`), what something more trusted runs later (`persist.autorun`: git hooks, `.envrc`, install scripts, launch agents) and another agent started without its own approvals (`self.nested-session`).
- **Full autonomy, as a way of working** ([docs/autonomy.md](docs/autonomy.md)): `/9` or `full auto`. A step you clearly asked for in your own words goes on once Claude quotes you and code finds the sentence in what you typed. The end of each turn reaches you as a notification, on your phone too through ntfy.
- **The cockpit** (`/0`, [docs/design.md](docs/design.md#the-cockpit)): a panel beside the conversation that says in words what Claude may do right now and why, what is at work, what waits for you and the quota, with quick settings.
- **A control center arranged by what you come for**: Now · Activity · Working · Protection · Memory and projects · Quota · Claude Code · Settings. Every setting says what it is, how it is now, what each other value would do and how to take it back; every change is recorded and can be undone; the mouse works; `/why` says why something is as it is.
- **What a task costs** ([docs/quota.md](docs/quota.md)): `mode-code measure` prices each task on your computer and says how the work held; in autonomous work, a large conversation starts again from a note at a task boundary, measured at 14 to 19% of the whole quota on the author's month.
- **Parallel agents** ([docs/agents.md](docs/agents.md)): how many agents Claude starts, set by you for each session on the strip.
- **Skills and tool packs** ([docs/skills.md](docs/skills.md), [docs/packs.md](docs/packs.md)): 22 skills of Mode_Code's own that you run (verify, a second opinion, release and pull request preparation, store readiness …), 33 skills by others off until you turn one on, and tool packs turned on only in the projects that need them.
- **Measured, with its limits said** ([docs/threat-model.md](docs/threat-model.md)): a threat model, four public attack sets and three sets of other agents' everyday work replayed through the belt in each way of working, and every limit found.
- **Updates and a first installation anyone can read**: `mode-code update` checks a release against its checksums and installs it; the installation asks its five choices as a short setup and says what it does in plain lines.

### Upgrading from 1.1

- **How:** run the one-line installer again (the [Install](https://github.com/OzcanOrhanDemirci/Mode_Code#install) line above); from 1.2 on, `mode-code update` does it. Settings, history and handoff notes are kept. What changed is said once, at the end of the update and as the next Claude Code session starts.
- **Bypass is gone.** In 1.2 the protection is the same in every way of working and the way of working says how much is asked. A `bypass` section in the settings file is read without a problem and does nothing.
- **Full-autonomy runs are gone,** with `mode-code autonomy`, `mode-code memory notes` and the `autonomy` settings: full autonomy is `/9` or `full auto`, a way of working like the others. A new session never takes it up by itself: the folder's last choice comes back as Autonomous.
- **`/0` shows the cockpit** instead of opening the control center, which is one press from it (**Control center…**); where no pane can be drawn, `/0` opens the control center as before. On the strip `9` is full autonomy.
- **The control center's pages moved** to the eight new categories. Every old address still opens its page, and the palette finds a page by its old place.
- **Manual asks a little more:** setting git's hooks path, deleting or moving memory files and discarding uncommitted work are asked, and `git commit --no-verify` is asked rather than noted (`mode-code config set belt.verdicts '{"git.no-verify":"warn"}'` makes it a note again).
- **Unchanged:** Claude Code 2.1.290 or newer for the plugin (2.1.295 for the safety-net hook) and Node.js 22.13 or newer.

### Added

What it lets through is recorded call by call and counted on the strip in red letters (not filled, so the ⚡ stays visible); Claude Code's own mode questions are answered too, while a rule in Claude Code's settings keeps its question. - The control center's eighth category, Automation: full autonomy (moved from Settings), its runs (moved from Projects), bypass, and Done without asking, every call bypass let through with what it passed, by whom and how it went. Digits 1-8 jump to the categories.
- Full autonomy opens with a click: `full auto` on the strip (or `/tam-otonom`) opens a window where the budget is picked (+5, +10 or +20, each with the weekly limit it sets) and the task written; Start or Enter sends the task as the person's message ending in the keyword, so the start checks and the run are the keyword's. Esc closes the window and keeps the task for the next time. On a phone, which draws no field, it asks as before.

## [1.0.0] - 2026-10-15

It finds or installs git and the GitHub CLI with your system's installer, signs you in, names and creates the private repository (a public one is refused), brings the memories you already have along, lists every change and asks once; Claude Code's settings are backed up before `autoMemoryDirectory` is written. The memory is pulled when a session starts (what came in is told to Claude with the first prompt, since Claude Code may have loaded the index before the pull landed) and committed and sent after a turn that changed it; a file that looks like it holds a secret is held back, a conflict is undone and shown, nothing is forced.

They are kept in the memory under `handoffs/<project>/` and synced; the next session is told about the newest on its first prompt and gets the whole note on `continue`.

Nothing is added to such a folder, and handoff notes go into it only when you want. What arrived since this computer's last session, whoever brought it in, is told to Claude.
- Sync across computers ([docs/sync.md](docs/sync.md)): `mode-code sync setup` shares Mode_Code's settings, history and handoff notes through a private repository on your GitHub that you name (a folder of it when it holds other files, through a copy you may already have) or a folder another service keeps in sync. Each computer writes only its own folder. The newest change of a setting wins on every computer; one that lowers a protection waits for you (`sync approve`, `sync ignore`). Paths, full autonomy switched on and the quota reading stay each computer's own. The morning report says what the other computers did; `mode-code sync` (status, setup, now, approve, ignore, project), Settings › Sync, and the doctor's check.

- Session controls ([docs/modes.md](docs/modes.md#session-controls)): the mode and the way of working (manual, autonomous, full auto) are always in view on a strip above the prompt, and change in one step from the strip (a click, or ctrl+x tab and Enter), a slash command or the keyword typed alone. `/1` … `/5` set the mode, `/6` `/7` `/8` the way of working, `/9` starts a flow, `/0` opens the control center in a new tab of the terminal (Windows Terminal, tmux, iTerm2, WezTerm, Konsole, GNOME Terminal; a window elsewhere; from the phone it lists every command instead); `/2 <text>` switches and sends the text. They act at once, mid-turn too. `/devam` lists the registered projects and every folder Claude Code was used in, and continues one by number or name (`/devam 3 kota 29`); `/kota` asks for a weekly budget; `/9` asks which steps and takes the next message as the task; `/8` runs the start checks first, then asks for a budget and a confirmation. A plain digit stays a message.
- A new session (and the one after /clear) starts in the mode and way of working last used in its folder, says so, and tells Claude.
- `/00` (`/kapat`, `/close`, and `00 ✕` on the strip) closes the session cleanly, the way a shut-down differs from the power button: the handoff note and the sync run first, with no clock running, then Claude Code exits as for `/exit`, its own end hooks included.
