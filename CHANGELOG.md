# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `/freeze <folder>` (`/dondur`): every write a call names stays inside one folder (and the temporary folders) until you end it; `❄ <folder>` on the strip while it holds. Only you set it.
- Claude Code's question about a compound command (`cd app && npm test`, `npm run build && npm test`) is answered for you when each of its parts is one your allow rules already cover; a `cd` into the project only says where the rest runs. A part no rule covers, a redirect into a file or a nested command is asked as before.
- Outside content taints a session: after it read a web page, an issue, a page fetched with `curl`, a connected service's data, a dependency's files or another session's message, sending data out, writing what starts by itself or configures Claude Code, and writing the memory are asked about, with bypass on too (`inject.tainted-act`, `docs/safety-belt.md`).
- A key or token pasted into your message is told to you (it went to the model provider with the message; rotate it if it was a mistake), and Claude is told not to repeat, store or send it. The kind only, never the value.
- A safety-belt rule for the project's own checks: changing the settings of a linter or a formatter (ESLint, Prettier, Biome, `analysis_options.yaml` …) is asked about, by any tool (`quality.check-config`).
- A memory push is held when a commit it would send adds a secret, a commit made by hand included; you see the file and the kind, never the value, and `mode-code secrets allow <fingerprint>` lets a false alarm go (`docs/memory.md`). The same holds for the sync across computers.
- `mode-code update`: whether a newer release is out, read from the release's `SHA256SUMS`, and the update to it with the release's own installer, downloaded and checked against that file, run with `--yes`, then the new installation's doctor. Also `u` under Maintenance in the control center. Only you start it: never from inside a Claude Code session.
- A daily update check, asked at install and off until you say yes (`update.check`): one small download from the release, nothing sent. A newer release shows in the doctor, the `/0` menu, the morning report and under Maintenance.
- `node scripts/claude-compat.mjs` for development: Mode_Code against the installed Claude Code (check, the mod's types and engine kit, optionally the live sessions), recorded as a row in `docs/testing.md`. A red nightly run against the newest Claude Code opens an issue labeled `claude-code-compat`.
- What a task costs of the quota, measured on your computer (`node scripts/measure/tasks.mjs`): every Claude Code session cut at its commits and pushes, each piece priced by model and token kind, weighed by what the quota counts, and turned into weekly points by Mode_Code's own readings. It reads the transcripts and the event log and writes nothing (`docs/testing.md`).
- `mode-code sync projects`, also run by the sync setup: projects that came from another computer find their folder here by the same repository, the folder name the other computer uses or their own name, and are linked on one yes. Each computer's `machine.json` now says where it keeps its projects, with no user or token in a repository's address (`docs/sync.md`).

### Changed

- `git commit --no-verify` (and `-n`, and `git push --no-verify`) is asked about rather than noted: skipping the repository's own hooks is how a change slips past its lint, tests and secret checks. Turn it back into a note with `mode-code config set belt.verdicts '{"git.no-verify":"warn"}'`.
- Checked against Claude Code 2.1.302: the plugin type-checks against its declarations, the engine's own test kit passes, and the live sessions run on it.

### Fixed

- A Windows path written through the device namespace (`\\.\C:\Users\you`) is read as the same file as `C:\Users\you`: deleting the home folder that way is blocked, as it already was through `\\?\`.
- The safety-net hook refuses a tool call whose input reached it cut short or garbled, instead of letting it through unjudged.
- The session's controls (the mode, the way of working, the budget, the menu, closing, continuing) refuse a command that Claude Code stamps as coming from a prompt Claude scheduled for itself, another session, a background notice or another plugin, as bypass and full autonomy already did; before, those could change the mode or raise the budget.
- The safety belt asks about code piped into a shell or an interpreter (`curl … | sh`, `… | base64 -d | bash`, `… | python3 -`) and about `bash <(curl …)`, as it already did for PowerShell's `| iex`; before, those ran unasked.
- A command that only reads the hooks-off setting (a `grep`, a `jq` lookup) is no longer blocked when something else in it changes files; giving the setting a value that turns hooks off is blocked as before.
- At the quota's hard limit, staging (`git add`) is allowed with the commit it prepares, as the refusal message always said; before, saving memory could not finish.
- Yes/no questions use the letters of your language in one case (`[e/h]` in Turkish, not `[Y/n]`) and say what Enter answers, so the memory and sync setups' last question, where Enter means no, no longer cancels unnoticed.
- The installer's question about the footer lines says what each choice does and shows two lines as they would appear; before, it listed only the names.
- An installation that asks no questions (the simple view, `--yes`, the one-line installers) protects the memory folder Claude Code is set to keep (`autoMemoryDirectory`); before, it protected none.
- The sync setup offers a Mac its own name from System Settings; it offered the host name, which a network can set to the computer's address (`192.168.1.9`). An address is never offered as a name.
- A handoff note's next step, when it is only the last request, is named in your language on the screens and in `mode-code memory`; it said "last request" in English.
- Uninstalling leaves Claude Code's `settings.json` as it was: the empty `enabledPlugins` and `extraKnownMarketplaces` that Claude Code leaves behind are removed with the plugin's own records.
- A memory folder already protected under another spelling (`~/notes/` beside `/Users/you/notes`) is not added again by the memory setup, and the doctor counts each folder once.
- In Apple's Terminal, Mo beside a strip of two rows is drawn one row tall: the half blocks of the two-row Mo leave a gap between rows there, and it read as two Mos stacked.
- On a Mac, the window `0` opens for the control center clears the command it typed before the program starts; Terminal showed it twice.

## [1.1.0] - 2026-10-15

One roof for every guard, and bypass: the safety belt takes over the permission lists and command guards that stood beside it and covers what they missed, a session can lift it for a while on the person's word with every call recorded, the strip shows the flow as a mode whose working step breathes, and the control center gains Automation.

### Added

- A keyword typed with a slash in front (`/akış iptal`) is that keyword, and a notice says how it was read; a message one typo from a keyword (`akış iptl`, `serbes`) is offered ("did you mean …?") and never applied.
- Safety belt: nine rules, 48 in all. Deleting data in the cloud (Firebase, storage buckets, managed databases, cloud projects, a GitHub repository) is blocked; overwriting a live Firebase database and dropping or resetting a database are asked. Turning off or weakening security software (Defender and its exclusions, the firewall, account control, Gatekeeper, SELinux) is blocked. Merging a pull request with admin rights past the required checks, and deleting or archiving on GitHub, are asked. A secret leaving the computer (a key or credential file uploaded, a secret in a request body, a message or a document) is blocked, locked, without exception.
- Safety belt: calls to connected services (MCP servers) are checked. Sending, replying, forwarding, sharing, inviting and calendar events are asked; deleting or trashing there is asked; reading is not.
- Bypass tiers in the rule catalog (`docs/safety-belt.md`, "Bypass"): self-protection and secrets never lift; deleting a drive root, a system folder or cloud data, formatting a disk and turning security software off are blocked without bypass and asked with it; the rest is let through with bypass on and recorded. A block of the second tier says how bypass changes it.
- The rules of an older setup folded into the belt, each with a sample it must ask about or block: 78 permission rules from Claude Code's managed settings and a memory system's command guards (`test/corpus/automation-parity.test.ts`).
- The flow is one of the modes on the strip (`6`), the one that moves between the others by itself. While it works it is lit and the mode of its step breathes, gray to white and never filled, drawn on Claude Code's own clock; waiting for approval nothing breathes; paused for another mode its button shows `⏸`. Pressed: off, it asks which steps; on, it closes the flow (its record stays); paused, it goes on. With less motion asked for, and on a phone, the step's mode is marked instead.
- Bypass (`docs/autonomy.md`, "Bypass"): lifts the safety belt in one session for a while (`bypass.maxHours`, 2 by default), turned on per computer first and then by the person in each session (`/bypass` or `⚡ bypass` on the strip, asked once). Only the person can switch it, or full autonomy: a command stamped as coming from elsewhere is refused. What it lets through is recorded call by call and counted on the strip in red letters (not filled, so the ⚡ stays visible); Claude Code's own mode questions are answered too, while a rule in Claude Code's settings keeps its question. Claude is told it has full authority and full responsibility, with a reminder each prompt. It ends at its time (warned ten minutes before), with the session, or when the setting is turned off, with a summary line. The safety-net hook reads it from the session's record, so both layers agree.
- The control center's eighth category, Automation: full autonomy (moved from Settings), its runs (moved from Projects), bypass, and Done without asking, every call bypass let through with what it passed, by whom and how it went. Digits 1-8 jump to the categories.
- Full autonomy opens with a click: `full auto` on the strip (or `/tam-otonom`) opens a window where the budget is picked (+5, +10 or +20, each with the weekly limit it sets) and the task written; Start or Enter sends the task as the person's message ending in the keyword, so the start checks and the run are the keyword's. Esc closes the window and keeps the task for the next time. On a phone, which draws no field, it asks as before.
- Automation › Recent tasks: the last three tasks given full autonomy, from the window or typed, kept so none is lost; the one picked shows whole, and Enter or `c` copies it (the system's clipboard tool, else the terminal's).

### Changed

- Checked against Claude Code 2.1.300: the plugin type-checks against its declarations, the engine's own test kit passes, and the live sessions run on it.
- Deleting or moving this tool's folder or Claude Code's folder is self-protection (`self.tool-files`, `self.claude-settings`), no longer a critical folder: no setting and no bypass opens it.
- Deleting a Docker volume (the optional pack), outside the project, a `.git` folder or staging a secrets file are asked even with bypass on.
- Full autonomy pressed on the strip while a run is attached ends the run, as `full auto cancel` does; it used to only repeat where the session stood.
- The strip's numbers: `6` is the flow, `7` manual, `8` autonomous. Full autonomy has no number (`/tam-otonom`, `/full-auto`) and is on the strip only once turned on, no longer gray for everyone; `9` is free.
- Full autonomy runs on native Windows too. There is no sandbox there, so a run is guarded by the safety belt and the fence alone, which turning it on says plainly; the fence also refuses a write a shell command names outside the project, the temporary folders and the run's folder, as it does a file tool's. It used to be refused there, while Automation let it be turned on and the strip showed it gray. The live sessions now run a whole run on Windows (`node scripts/test-live.mjs --yes --only-auto`).
- A start check in Automation › Full autonomy wraps onto the next line instead of being cut short.
- The strip's menu (`0 ≡`) and closing (`00 ✕`) stand apart at the far end of the row, as a window's own buttons, no longer as the last two of the way of working.
- Presses on the strip close together count as the last one: the strip and the rules change at once, and Claude hears the end state once, a moment after the last press or with the next message, not every step on the way.

### Fixed

- A flow's verification commands run where the session's shell is, which the plan step did not say: a flow opened from the home folder for a project elsewhere had its plan's `npm run verify` fail at the code step with no word of the folder. The plan step now names the folder the commands run in and how to name another (`cd <folder> && npm test`), and a failed command says where it ran.
- The terminal's cursor flickered under the person's typing, about seven times a second: every frame Claude Code draws hides and shows it, and Mo breathed at rest, the flow's step too between turns. Mo now moves only while Claude works and while something that just happened shows, and is not drawn again at rest; the flow's step breathes only while Claude works and is marked between turns. Measured in a pseudo console at rest: 69 cursor hide-and-show pairs in ten seconds before, 1 after.
- Toasts were cut after three lines with "…", often where they said what to do: a press on the strip showed a control's whole answer, and full autonomy's refusal came as a list whose line breaks were drawn as marks. A press shows one line now; full autonomy's refusal says its reason in plain words with what to do ("this folder is not a git project. Open Claude Code in the project's folder", where it used to say only "Project"), or, when several checks failed, how many and where to read them; nine texts are shorter, and a detail of any length (an error) comes last. A test wraps every line the plugin shows as a toast the way the box does, in both languages (`test/core/toasts.test.ts`).
- Repositories cloned over SSH (`git@github.com:me/app.git`) escaped the pull-request-only and one-branch rules: the remote kept its colon and matched no `github.com/me/app` rule. Every spelling of a remote is now the same repository, on both sides of the comparison.
- Package runners in PowerShell (`npx`, `pnpm dlx`, `bunx`) were not read as the program they run, so `npx firebase database:remove` in PowerShell went unchecked; in bash it was.
- Full autonomy turned off while a run worked did not pause it, though the documentation said it would; it pauses at its next step now, and the settings are read again at most once a minute during a run or bypass, not only at the next prompt.
- A run resumed after its time limit paused again at its very next step: the limit kept counting from the start. Resuming after a time-limit pause starts a fresh limit; the running time itself goes on counting.
- A run paused by code said "no measurable progress" whatever the reason; it names the reason (time limit, turned off, …).
- After a full-autonomy run, the next session in that folder started autonomous even when the person had worked manually before it; it starts as the way of working before the run.
- Two messages named the way to let a full-autonomy run go "full auto flow cancel" ("tam otonom akış iptal"); the keyword is "full auto cancel" ("tam otonom iptal").
- Two sessions starting at the same moment broke the memory and settings sync ("Cannot rebase onto multiple branches", "Cannot fast-forward to multiple branches", told as both sides having moved): each ran `git pull`, which reads `FETCH_HEAD`, and two fetches at once fill it with several heads. Changes now come in with a fetch that leaves `FETCH_HEAD` alone and a join with the branch the folder follows, made once more when another git holds a lock. Three pulls at once in one clone, twenty times over: 3 of 60 went through before, 60 of 60 now.
- Installing over an earlier version left Claude Code's record of the plugin at the earlier version, so the doctor warned, and its repair (copying the files again) could not clear it. The plugin is read in place from its folder, so the new version did run. The installer now has Claude Code record the version it installed (`claude plugin update`), and the doctor judges the version that loads; its repair for another version copies the files and updates the record.
- Chat, research and plan mode no longer refuse reading commands that ask about machine-wide packages (`npm root -g`, `npm ls -g`, `npm outdated -g`): `-g` counted as a machine-wide install before the reading subcommand was looked at. They also run this tool's own commands that only print (`mode-code status`, `mode-code belt rules`, `mode-code memory handoff`, `mode-code config get` …); `mode-code` on its own, `doctor`, and the commands that change settings or the session index are still refused there. `pnpm store prune` is no longer taken for a read.

## [1.0.0] - 2026-10-15

The first public release: the safety belt, keywords, modes and flows, full autonomy, the memory and its sync, the quota guard and the control center, installed with one line.

### Added

- One-line installers: `curl -fsSL …/install.sh | sh` on macOS and Linux, `irm …/install.ps1 | iex` in Windows PowerShell 5.1 and PowerShell 7. They use the Node.js on PATH, or download the official Node.js 24 build for Mode_Code alone (checked against nodejs.org's SHA-256 list; no administrator rights, no sudo); download the newest release and check it against its `SHA256SUMS`; put the program in `~/.local/share/mode-code` (`%LOCALAPPDATA%\mode-code`) and the `mode-code` command in `~/.local/bin`, adding that folder to PATH once, marked; then run `mode-code install`. Without Claude Code they offer Anthropic's official installer. Running one again updates; `--yes`, `--version`, `--no-modify-path` and `--no-setup` (`-Yes`, `-Version`, `-NoModifyPath`, `-NoSetup`) for scripts. Inside a Claude Code session they refuse, and a `mode-code` command they did not write is never replaced.
- `mode-code uninstall` also removes what the one-line installer put in place, from the record it left: the program folder, the `mode-code` command and its PATH entry, the entry only when no other program in that folder needs it. On Windows, the Node.js running the removal is deleted by a helper the moment it ends. `--keep-program` leaves the program.
- Releases from a version tag: the tag, `package.json`, the changelog and the installers must agree, every check passes, and the installers install the very package the release carries on Linux, macOS and Windows before the release is made, with `SHA256SUMS` and a build provenance attestation.
- The README's pictures are drawn by the control center itself from sample data (`npm run screenshots`).
- Mo, the mascot: a small robot at the left of the strip above the prompt that shows at a glance what Claude is doing (resting, thinking, at a tool, with agents, in full autonomy, waiting for you) and what just happened (done, stopped, failed, a call refused). It greets you in the control center and when the installation finishes. Off with `modules.mascot`, still with reduced motion; its pictures in the repository are drawn from the same pixels (`npm run mo-art`). See `docs/mo.md`.
- Safety belt: 39 rules over bash, PowerShell and cmd commands and file writes, with locked self-protection rules; runs in the in-process plugin and in a safety-net hook that blocks on failure.
- Keywords in English and Turkish (`continue`/`devam`, `quota 40`/`kota 40`, `chat`/`sohbet`, `wrap up`/`toparla`, `stop`/`dur` …), robust to Turkish keyboards and typos.
- Quota guard: wraps up at the budget, stops at the limit, resumes autonomous work after the reset.
- Footer lines under each answer, drawn by the plugin or written by the model and checked by a hook.
- Quiet long work: Claude Code's "the user has not heard from you" reminders are left out.
- Chat mode enforced by code: no project or memory writes until you pick another mode.
- Control center with seven categories, three columns, addresses, a go-to palette, filters, view levels, plain and high-contrast modes, settings edited in place.
- Session index in SQLite: incremental, each API message counted once, secrets masked.
- Commands: `status`, `doctor`, `install`, `uninstall`, `quota`, `tokens`, `sessions`, `belt`, `secrets`, `config`, each with versioned `--json` output.
- Installer that shows every change, asks once, backs up the settings, records a manifest and self-tests; removal undoes exactly the manifest. Running it again repairs an installation.
- `mode-code try`: one Claude Code session with everything loaded, without installing.
- Quota history on the quota screen, from readings the plugin records.
- Settings changed in the control center apply to running sessions at the next prompt.
- The session state (autonomous work, project, weekly budget, chat mode) survives a compaction; /clear starts fresh.
- Footer lines are drawn inside the answer, and the mode and quota beside the prompt, without notice prefixes.
- Rule templates (public repository, pull requests only, one branch, production server, Flutter, measure before claiming, plain writing): a few lines in the folder's CLAUDE.md and, for some, a tighter belt; `mode-code template` and Claude Code › Rule templates.
- `mode-code report` and Measure › What happened: the last day or week in a few lines.
- A warning, for the person and for Claude, when another Claude Code session is working in the same folder; Home lists such folders.
- After a quota reset, autonomous work resumes with a prompt that ends with your own continue keyword.
- `mode-code doctor` measures the machine, checks the installation and the protections, runs the built-in self-tests, compares the installed hook program with this build on the same samples, and offers safe repairs that back up, restore and check again (`--fix`, `--report`, `--quick`, `--self-check`, `--json`). The maintenance page shows the last check.
- `mode-code belt replay`: the belt run over your recent sessions, counting what it would have asked about or blocked, by rule. Nothing is run.
- A test process with sixteen layers, from invariants about the code to real Claude Code sessions and an antivirus, and `npm run verify` to run every layer that can run on a machine. See [docs/testing.md](docs/testing.md).
- Modes, enforced by code: chat, research, plan and code (`sohbet`, `araştırma`, `plan`, `kod`; `serbest` for free). Chat, research and plan write only into temporary folders, the flows' work folder or the plan file, and run a shell command only when they can place what it does: a classifier sorts every program a command runs into reads, writes named files, changes around its folder, changes outside, or unknown, and refuses what it cannot place, saying why. See [docs/modes.md](docs/modes.md).
- Flows: `flow` / `akış` (research ▶ plan → approval → code), `flow plan`, `flow research`. Steps run in order and the model finishes one through the `flow_step` tool; code checks each: a report whose findings cite sources that exist, a plan with numbered steps, acceptance criteria and verification commands the belt allows, the person's approval (the plugin's dialog, Claude Code's plan dialog, or `approve` / `onay`), and verification commands that pass when the plugin runs them. Flows pause, resume across sessions and survive a compaction.
- Claude Code's plan mode is bridged: its plan mode puts the session in plan mode, and its plan dialog approves a flow's plan after the plugin has checked it.
- `mode-code flow`, Projects › Flows, and plans waiting for approval on Home and in the inbox.
- `belt replay` also says what the restricted modes would run of your recent shell commands; `doctor` runs a modes self-test.
- Full autonomy: `<project> full auto quota +N` / `<proje> tam otonom kota +N` runs one task to its end with nobody at the keyboard. It starts only after code measured its start checks: turned on by the person, an explicit budget, WSL2 with interop off and no Windows drive mounted (native Windows is refused), Claude Code's sandbox in its strict form, a live probe in which the operating system refuses a write outside the project, a permission mode that never waits for an answer, the safety-net hook running, a clean git work tree. A run plans (the plan's verification commands only grow, the person's `projects[].verify` always among them), reaches a milestone per step on a commit of its own with a rollback reference and an independent review (one model call that sees the request and the diff, never the conversation), and finishes only when every verification command passes and a final review does not fail. See [docs/autonomy.md](docs/autonomy.md).
- During a run nothing is asked: what the belt would ask about, pushes to protected branches, merges, releases, outward tools and Claude Code's own permission questions are refused as deferred, recorded with the exact command and listed in the run's report; unknown tools, questions for the person, writes outside the project, credential reads, memory folders and the sandbox's escape hatch are refused.
- The safety-net hook keeps an unfinished run from stopping, unless code measures a reason: the run is over or paused, the budget or the time limit is reached, background work will wake the session, or three attempts to stop changed nothing.
- `mode-code autonomy` (list, show, report, check, enable, disable, rollback), Settings › Autonomy with what turning it on means, Projects › Runs, open runs on Home, ended runs in the inbox, a doctor check.
- The memory ([docs/memory.md](docs/memory.md)): `mode-code memory setup` decides where Claude Code's memory lives (this computer, a private repository on your GitHub, or both). It finds or installs git and the GitHub CLI with your system's installer, signs you in, names and creates the private repository (a public one is refused), brings the memories you already have along, lists every change and asks once; Claude Code's settings are backed up before `autoMemoryDirectory` is written. The memory is pulled when a session starts (what came in is told to Claude with the first prompt, since Claude Code may have loaded the index before the pull landed) and committed and sent after a turn that changed it; a file that looks like it holds a secret is held back, a conflict is undone and shown, nothing is forced.
- Handoff notes: `handoff` / `devir` (and `wrap up`) has Claude write where the work stands through a tool; notes are also written from a compaction's own summary, when a session that changed something clears or ends, and when a full-autonomy run pauses or ends. They are kept in the memory under `handoffs/<project>/` and synced; the next session is told about the newest on its first prompt and gets the whole note on `continue`.
- The morning report: one line on the first prompt after a while away, the full report in `mode-code morning` and on Home. Notes from full-autonomy runs wait for your approval (`mode-code memory notes`).
- `mode-code memory` (status, setup, sync, handoff, notes) and `morning`; Settings › Memory and Projects › Handoffs in the control center; the doctor checks the memory store.
- A memory you keep in sync yourself: the setup asks, for a folder that already has a git history, whether Mode_Code keeps it in sync, only brings in changes when a session starts (a fast-forward; you commit and push), or leaves git to you. Nothing is added to such a folder, and handoff notes go into it only when you want. What arrived since this computer's last session, whoever brought it in, is told to Claude.
- Sync across computers ([docs/sync.md](docs/sync.md)): `mode-code sync setup` shares Mode_Code's settings, history and handoff notes through a private repository on your GitHub that you name (a folder of it when it holds other files, through a copy you may already have) or a folder another service keeps in sync. Each computer writes only its own folder. The newest change of a setting wins on every computer; one that lowers a protection waits for you (`sync approve`, `sync ignore`). Paths, full autonomy switched on and the quota reading stay each computer's own. The morning report says what the other computers did; `mode-code sync` (status, setup, now, approve, ignore, project), Settings › Sync, and the doctor's check.

- Session controls ([docs/modes.md](docs/modes.md#session-controls)): the mode and the way of working (manual, autonomous, full auto) are always in view on a strip above the prompt, and change in one step from the strip (a click, or ctrl+x tab and Enter), a slash command or the keyword typed alone. `/1` … `/5` set the mode, `/6` `/7` `/8` the way of working, `/9` starts a flow, `/0` opens the control center in a new tab of the terminal (Windows Terminal, tmux, iTerm2, WezTerm, Konsole, GNOME Terminal; a window elsewhere; from the phone it lists every command instead); `/2 <text>` switches and sends the text. They act at once, mid-turn too. `/devam` lists the registered projects and every folder Claude Code was used in, and continues one by number or name (`/devam 3 kota 29`); `/kota` asks for a weekly budget; `/9` asks which steps and takes the next message as the task; `/8` runs the start checks first, then asks for a budget and a confirmation. A plain digit stays a message.
- A new session (and the one after /clear) starts in the mode and way of working last used in its folder, says so, and tells Claude.
- `/00` (`/kapat`, `/close`, and `00 ✕` on the strip) closes the session cleanly, the way a shut-down differs from the power button: the handoff note and the sync run first, with no clock running, then Claude Code exits as for `/exit`, its own end hooks included. On Windows the terminal tab goes with it: a helper started before the exit waits for Claude Code to end and types `exit` into the shell it was started from, so the tab closes as for any shell that ends normally. While Claude works, `/00` asks first and stops the turn only when confirmed. Asked for by the author after a tab closed with its ✕ left Claude Code running unseen behind it.
- The flow `flow research plan` / `akış araştırma plan`: research ▶ plan, with no code.

### Changed

- The tool is now called Mode_Code (it was terminal-code). `mode-code install` moves an installation made under the old name: its settings and history are copied, its hooks swapped for the new ones in one write, its plugin and folder removed once the new installation tested itself. Environment variables are now `MODE_CODE_*`, and the JSON contracts' schema names start with `mode-code.`.
- The words that switch the mode (`plan`, `kod`, `sohbet`, `araştırma`, `serbest`) count only as the whole message: "Bu bir plan." no longer switches modes, and inside a flow a mode word at the end of a longer message no longer changes that turn. `manuel` and `otonom` alone set the way of working. A budget at the very end of a sentence counts ("bunu da yap kota 29").
- Manual work means what the author meant by it: Claude does what the message asks, says what it did and what would come next, and waits; it asks when a decision is the person's.
- The mode and the way of working are always shown beside Claude Code's own labels, the defaults (free, manual) too.
- The mode and the way of working change only when you name them: on the strip, with `/1` … `/8`, a mode or `manuel` / `otonom` typed alone, or `manuel` in `manuel <proje> devam`. `continue` no longer turns the session autonomous or leaves chat mode, a budget at the end of a task no longer turns it autonomous, `stop` no longer resets it, and a full-autonomy run gives back the way of working it took over when it ends. Continue now tells Claude the mode and the way of working it leaves as they are. A new session also takes up a manual you picked in the folder, not only a mode or autonomous work. Reported by the author: chat and manual on the strip, then `terminal devam`, and the strip showed free and autonomous.
- Full autonomy's independent reviews see the project beyond the diff: the tracked files and the build manifests at the reviewed commit; the final review also gets the verification results. Measured in live runs: the reviews' false alarms about files the diff did not touch stopped.
- Package runners are read as the program they run: `npx wrangler deploy` is asked about like `wrangler deploy`.
- Publishing and deploying with `--dry-run` are no longer asked about.
- When an agent runs `doctor`, repairs that would put code into the protection are refused and left to the person.
- Text widths are measured the way the terminal draws them (emoji and symbols such as 🛡 ⚪ ✅ ⛔ included), so no line is cut or wraps.

### Fixed

- A keyword typed before a paste was not seen (`terminal devam (<paste>)`): the end of the message was the paste's closing bracket. What you paste is now material, not your words: the keyword around it counts as it would at the end, what is inside it never does. Found when a session started that way was not that project's, and its handoff note went under the folder's name.
- The first prompt of a session that took up the folder's last choice told Claude the choice it started from, not what held after a press on the strip or the prompt's own keyword; it now says what holds, once.
- `/0` did not open the control center in Windows Terminal in a session started in the home folder: Claude Code refuses to find a program by name in Windows' app alias folder when the session's folder contains it. Windows Terminal is now run by its alias's full path (a link only; a program copied there is not taken), and a failed `/0` keeps its reason in the event log. Found by the author's first `/0` in a real session.
- A session closed a moment ago still counted as working in its folder for 15 minutes: the next session there was warned of it, and so was Home. A session now marks itself ended first thing when it ends, and one closed without ending (its window shut) is found by its process: the safety-net hook records the Claude Code process each session runs in, and before anyone counts a session as working its process is looked up (on Windows, by its number and its program, as Windows hands numbers out again soon). A flow or a run left by such a session is free to take over at once, and the control center's "Running now" no longer lists it. Reported by the author: two sessions closed minutes before were said to be working beside a new one.
- A session closed without ending left no end note. Its record now keeps, from its first change, what that note is written from (when it started, when it last changed something, its project, the last request), and the next session to start writes the note it owed, once (`trigger: closed`), and is told of it.
- The doctor said Claude Code keeps one memory per project when its memory folder was set outside Mode_Code; it says where the memory is now.
- The memory setup gave a folder inside a larger repository, chosen for this computer only, a git history of its own inside the other; it is used as it is now.
- The README said nothing leaves your machine; the memory and sync go to a private repository of yours when you set them up so, and it says that now.

- A full-autonomy run never started in a real session: Claude Code runs the plugin's prompt hook before the safety-net hook's, and `SessionStart` carries no permission mode, so the start checks found the mode unknown. The start now has two steps: the checks measurable at the prompt there, the permission mode that prompt came with and the live sandbox probe at Claude's first step (the autonomy tool's `start`). Found in the first live run in WSL2.
- A command typed on Windows for a WSL distribution (`wsl -d dev -- rm -rf ~/dev/old`) was judged with the Windows home folder: the distribution's home and absolute paths are now its own, the Windows drives it mounts under `/mnt` keep Windows' protection, and deleting the distribution's root, home or system folders is refused.
- In the plugin, the folders registered as projects did not count as projects: a session started in the home folder asked about every recursive delete inside them. The hook and the command line had them.
- Windows 8.3 short names of protected folders (`MODECO~1`) were not recognised, and neither were protected folders that are links.
- On macOS and Linux every recursive delete under the home folder was blocked, inside projects too.
- Windows drops trailing dots and spaces from a name; a protected file spelled that way (`.claude./settings.json.`) was not recognised.
- A command containing a word such as `__proto__` or `constructor` crashed the parser.
- `install --json` and `uninstall --json` printed text before the JSON.
- A path whose last name trims to `.` or `..` resolved differently the second time.
- Scripts run by Claude Code's Monitor tool were not checked by the belt; they are now read like Bash commands, in the plugin and in the safety-net hook. Found by `doctor` on the author's machine.
- A session started in the home folder counted the user's own settings twice, as user and as project settings, and the doctor reported the safety-net hooks as duplicated.
- The doctor called a hook program from an earlier build of the same version "changed after installation". The installation now records the program's fingerprint, so an earlier build and a change are told apart; an older hook matcher is named as such, with the tools it does not check.
